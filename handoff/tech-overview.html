2 · How the system works

visitor ──► penpal page (GitHub Pages, static) │ ├── analytics: gtag.js dual-tagged ──► GA G-74QCBZFVWH (sitewide property) │ └─► GA G-WT36BHRC7X (Firebase dashboards) │ └── signup form ──► Firestore "penpalIntake" │ (project "dafcgoc", free Spark plan; │ create-only rules, nothing readable publicly) │ ├──► Apps Script poller (15 min, as nationalcgoc@gmail.com) │ ├─► Google Sheet "Penpal Intakes" (row per signup) │ └─► email notification ──► nationalcgoc@gmail.com │ └──► Admin dashboard /admin/ (Google sign-in + allowlist) charts · response table · PDF report
  • No servers, no cost. Static pages on GitHub Pages; Firebase free tier (a signup uses ~0.02% of the daily free quota); Apps Script and the Sheet run on the free consumer Google account.
  • Security lives in the Firestore rules (firestore.rules in the penpal repo — already published): the public form may only create correctly-shaped submissions; all reads require an approved signed-in dashboard user. Verified end-to-end 4 Aug 2026.
  • If Firebase is ever unreachable, the form falls back to opening the visitor's email app addressed to nationalcgoc@gmail.com — no submission is silently lost.
  • Website analytics: every page carries both GA tags, so data appears in the existing GA property and the Firebase console. File downloads, outbound clicks, and scroll depth come from GA4 "Enhanced measurement" (a property setting, on by default). Weekly and monthly summary emails are generated by ga4-reports.gs.

5 · Administering the dashboard

  • Super-admins (permanent, set in the security rules): arkady232@gmail.com and nationalcgoc@gmail.com. They see everything and manage the viewer list.
  • Adding a viewer: sign in as a super-admin → Viewers tab → enter their Gmail/Google-account email → choose scope → Add. Takes effect on their next sign-in.
  • Scopes: Responses + analytics (full view) · Responses only · Analytics only — analytics-only viewers see aggregate charts but can never read names, emails, or any raw submission (enforced server-side).
  • Removing a viewer: Viewers tab → Remove. Immediate.
  • Changing the permanent super-admin list requires editing firestore.rules and re-publishing — ask the webmaster.

6 · Making changes safely

  • Page copy / sections: edit index.html in the penpal dev repo, push, check the dev URL, then promote to prod.
  • Form fields: three places must stay in sync — the field in index.html, buildPayload() in js/penpal.js, and the matching validation line in firestore.rules (re-publish rules after). Optionally map a new column in the poller script.
  • Analytics tags: every page must carry G-74QCBZFVWH + G-WT36BHRC7X. Never re-introduce the retired G-9MLXG6SFE1.
  • Full technical docs live in the penpal repo: README.md (architecture) and SETUP.md (console steps).
